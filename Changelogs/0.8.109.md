# 0.8.109

A fix for reading a dyld shared cache opened from its main file alone, the way `objc-section --dyld-shared-cache` opens it: a read that crosses into another sub-cache no longer opens and maps that sub-cache's file again, so indexing an image of a split cache stops piling up mappings of the same file.

## Fixes

- Every read that crossed into another sub-cache assembled that sub-cache afresh, opening and mapping its file once more, and the mappings outlived the caches that made them. Indexing SwiftUI out of a macOS 14.4 cache held 250 mappings of one sub-cache file; over many images their page tables alone ran to hundreds of megabytes. Each sub-cache is now assembled once per image, and a cache's mapping goes away with the cache. Present since `0.1.0`; the mappings have outlived their caches since `0.7.0`.

## Compatibility

- Requires MachOKitExtensions 1.1.1 or later (was 1.0.0), the first release that assembles each sub-cache once. The other dependency requirements are unchanged.
- `dump` and `interface` output is unchanged.

## Requirements

- Swift 6.2+ and Xcode 26.0+ to build from source.
